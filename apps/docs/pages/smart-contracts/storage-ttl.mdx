# Storage Keys & TTL Extensions

## Instance vs Persistent Storage
Soroban implements state archiving logic. PulsePay utilizes specific storage tiers based on lifecycle data requirements.

- **Instance Storage:** Used for global configuration variables like `AdminAddress` and `ProtocolFeeBps`. These require minimal footprint but constant access.
- **Persistent Storage:** Used for individual stream records (`StreamKey(stream_id)`). This ensures stream definitions are not evicted if the stream length exceeds ledger history limits.

## Time-To-Live (TTL) Management
Stream storage entries are provisioned with a baseline TTL of `3110400` ledgers (approximately 180 days).

For streams exceeding 6 months, PulsePay includes a public `extend_ttl` function. The Node.js Indexer automatically triggers this function to pay rent and extend persistent storage prior to expiration, ensuring streams are never archived mid-flight.
